# Release Conventions — IBTool

These rules are binding for all code changes. They are referenced from
`CLAUDE.md` and `ai/core/constraints.md`.

---

## metadata.txt Invariants

- All 11 required keys must always be present and non-empty:
  `name`, `description`, `version`, `qgisMinimumVersion`, `author`, `email`,
  `about`, `homepage`, `tracker`, `repository`, `license`
- `license` must always be `GPL-2.0-or-later`
- `version` must be incremented before every release commit (semver: `MAJOR.MINOR.PATCH`)
- `changelog` must document every version's changes (most recent entry first)
- Never remove, comment out, or leave empty any of the 11 required keys

## LICENSE File

- A file named exactly `LICENSE` (no extension, US spelling) must exist at the
  repository root at all times
- **Never delete, rename, or move this file**
- The file contains the full GPL-2.0-or-later license text

## Release ZIP

- The release ZIP is built exclusively via `scripts/create_release_zip.py`
- `make zip` (pb_tool) is obsolete for publishing — do not use it for releases
- The exclusion list in `scripts/create_release_zip.py` is the authoritative
  source of truth for what constitutes productive plugin code
- When adding new modules or directories to the plugin, review them against the
  exclusion list:
  - **Include**: productive Python modules, UI files, translations, icons, config
  - **Exclude**: test code, CI scripts, developer tooling, documentation, IDE files

## Plugin Folder Name

- The repository root folder is `IB-Tool-3` (contains a hyphen)
- QGIS resolves this via `importlib.import_module`; the `__init__.py` registers
  a virtual `ibtool` package as a workaround
- The ZIP must contain exactly one top-level folder named `IB-Tool-3`
- Do not rename the folder or the ZIP without updating `scripts/create_release_zip.py`

## CI Requirements

- The `qgis-plugin-ci.yml` workflow must pass (green) before any release upload
  to plugins.qgis.org
- The workflow validates: structure, metadata, style (flake8), security (bandit),
  secrets scan (detect-secrets), ZIP build, and ZIP validation
- A `.secrets.baseline` file (generated by `detect-secrets scan`) should be
  committed to suppress known-false-positive findings

## Verification Before Release

Run locally before pushing a release tag:

```bash
python ci/qgis_plugin_validate.py --auto
python scripts/create_release_zip.py
python ci/qgis_plugin_validate.py --zip dist/*.zip
```
